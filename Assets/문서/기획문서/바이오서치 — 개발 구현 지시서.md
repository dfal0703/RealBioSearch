# **바이오서치 개발 구현 지시서**

## **1\. 개발 목적**

본 프로젝트는 Unity 3D URP 환경에서 제작하는 **2D 업무 인터페이스와 3D 검사실이 결합된 신체 검사 도큐먼트 시뮬레이터**다.

현재 개발 목표는 전체 콘텐츠 구현이 아니다.  
우선 다음 핵심 경험이 실제 플레이로 성립하는지를 검증한다.

진단 자료와 대화를 바탕으로 의심 부위를 추론하고, 검사를 실시해 생성된 자료를 분석한 뒤 기생체 감염 여부와 위치를 판정한다.

초기 개발 완료 범위는 **핵심 게임 루프와 튜토리얼 챕터**까지로 제한한다.

---

## **2\. 개발 원칙**

### **핵심 루프 우선**

모든 구현은 다음 흐름을 완성하는 데 우선 사용한다.

**검사 요청 수신 → 자료 조사 → 검사 실행 → 결과 확인 → 추가 판단 → 최종 보고**

이 흐름에 직접 기여하지 않는 기능은 후순위로 둔다.

### **단계별 플레이 가능 상태 유지**

각 개발 단계는 독립적으로 실행하고 검증할 수 있어야 한다.

여러 시스템을 동시에 확장하기보다, 한 단계가 정상적으로 작동한 뒤 다음 단계로 진행한다.

### **시스템과 콘텐츠 분리**

검사체, 장기, 검사 방식, 결과 자료는 이후 확장 가능한 구조를 전제로 한다.

단, 초기 단계에서 모든 조합을 제작하지 않는다. 튜토리얼에 필요한 최소 사례만 구현한다.

### **2D와 3D의 역할 분리**

2D 영역은 정보 처리와 판단을 담당한다.

* CLI  
* 문서와 라이브러리  
* 검사 설정  
* 결과 분석  
* 보고서 제출

3D 영역은 검사체의 존재감과 즉각적인 반응을 담당한다.

* 검사체 입장  
* 외형 관찰  
* 검사 반응  
* 장비 작동  
* 변이 및 비상 상황

3D 공간을 자유 탐색 게임으로 확장하지 않는다.

---

## **3\. 1단계 — 기본 플레이 공간 구축**

### **목적**

게임의 전체 화면 구조와 2D·3D 공간의 관계를 확정한다.

### **구현 범위**

* Unity 3D URP 프로젝트 환경  
* 고정된 검사 업무 화면  
* 3D 검사실과 검사체 표시 영역  
* CLI 영역  
* 라이브러리 영역  
* 검사 제어 영역  
* 시각 메모 영역  
* 건강 상태 영역  
* 최종 보고 영역

### **완료 기준**

플레이어가 하나의 업무 화면 안에서 2D 자료를 확인하고, 동시에 3D 검사체를 관찰할 수 있다.

이 단계에서는 실제 검사 논리나 복잡한 상호작용을 구현하지 않는다.

---

## **4\. 2단계 — 검사 사례 진행 구조**

### **목적**

검사체 한 명이 접수되고 종료되는 전체 생명주기를 만든다.

### **기본 흐름**

1. CLI를 통해 검사 요청 수신  
2. 진단 보고서와 첨부 파일 등록  
3. 검사체가 3D 검사실에 입장  
4. 검사 업무 활성화  
5. 최종 보고서 제출  
6. 검사 종료 및 다음 사례 대기

### **완료 기준**

내용이 단순한 임시 데이터여도 검사 요청부터 보고서 제출까지 한 사례가 끊김 없이 진행된다.

---

## **5\. 3단계 — 조사와 자료 관리**

### **목적**

플레이어가 검사 전 정보를 수집하고 정리하는 경험을 구현한다.

### **구현 범위**

* 진단 보고서 열람  
* 검사체 신원 및 검사 경위 확인  
* CLI를 통한 검사체와의 대화  
* 대화 로그 자동 기록  
* 파일의 사례 라이브러리 등록  
* 이미지 자료의 시각 메모 배치

### **자료 구분**

* 문서  
* 대화 로그  
* 오디오 + 파형
* 이미지  
* 검사 결과  
* 최종 보고서

### **완료 기준**

플레이어가 보고서와 대화를 통해 의심되는 신체 부위를 하나 이상 추론할 수 있다.

자료는 검사체별 사례 라이브러리에 일관되게 누적되어야 한다.

---

## **6\. 4단계 — 핵심 검사 루프**

### **목적**

게임의 핵심인 신체 부위와 검사 방식의 선택을 구현한다.

### **기본 흐름**

1. 검사 부위 선택  
2. 검사 방식 선택  
3. 검사 실행  
4. 검사 시간 경과  
5. 3D 검사 반응 발생  
6. 결과 파일 생성  
7. 라이브러리 등록  
8. 추가 검사 또는 판정 결정

### **검사 설계 원칙**

검사 결과는 정답을 직접 알려주지 않는다.

플레이어는 문서, 대화, 검사 반응, 생성 자료를 서로 대조하여 판단해야 한다.

초기 구현에서는 소수의 장기와 검사 방식만 사용하되, 서로 다른 조합이 다른 의미를 갖는다는 점을 검증한다.

### **완료 기준**

플레이어가 무작위로 모든 검사를 반복하는 것이 아니라, 기존 자료를 근거로 검사 부위와 방식을 선택하게 된다.

---

## **7\. 5단계 — 검사 위험과 상태 변화**

### **목적**

검사를 단순한 정보 획득 버튼이 아닌 위험한 판단 행위로 만든다.

### **구현 범위**

* 검사체별 제한된 검사 시간  
* 검사 방식에 따른 시간 소요  
* 위험한 검사에 따른 건강 상태 악화  
* 정확한 체력 수치 대신 간접적인 상태 표시  
* 반복 자극에 따른 검사체 반응 변화

### **설계 의도**

강한 검사는 유용한 반응을 얻을 가능성이 높지만, 정상 민간인에게 상해나 사망을 유발할 수 있다.

플레이어는 다음 선택을 반복해야 한다.

현재 증거로 보고서를 제출할 것인가, 더 위험한 검사를 진행할 것인가?

### **완료 기준**

검사를 계속하는 행동과 멈추는 행동 사이에 실제 판단 차이가 발생한다.

---

## **8\. 6단계 — 기생체 변이와 비상 상황**

### **목적**

기생체가 단순한 문서상의 정답이 아니라 실제로 존재하는 위협임을 보여준다.

### **구현 범위**

* 특정 조건에서 기생체 과자극 발생  
* 검사체의 외형 또는 행동 변화  
* 공격적 상태 전환  
* 3D 공간의 비상 장치 조작  
* 검사 중단 및 상황 종료  
* 관련 이미지와 사고 기록 생성

### **설계 의도**

변이는 일반적인 전투 시스템이 아니다.

평상시의 정적인 문서 업무를 갑작스럽게 붕괴시키는 예외 상황이어야 한다.

### **완료 기준**

플레이어가 검사 과정에서 위험의 전조를 인식하고, 변이 발생 시 즉각적으로 비상 대응을 수행할 수 있다.

---

## **9\. 7단계 — 최종 판정 시스템**

### **목적**

플레이어가 수집한 정보를 하나의 책임 있는 판단으로 마무리하게 한다.

### **초기 보고 항목**

* 기생체 감염 여부  
* 감염된 신체 부위

### **설계 의도**

보고서는 자동으로 작성되지 않는다.

게임이 보유한 내부 정답과 플레이어의 제출 내용을 비교해 사례 결과를 결정한다.

초기 개발에서는 기생체 종류, 위험 등급, 공생 여부 등의 추가 판정을 포함하지 않는다.

### **완료 기준**

플레이어가 검사 자료를 근거로 최종 판정을 제출하고, 그 정확성과 검사체 상태에 따른 결과를 확인할 수 있다.

---

## **10\. 8단계 — 튜토리얼 챕터 통합**

### **목적**

개별 시스템을 하나의 짧은 플레이 경험으로 통합한다.

### **튜토리얼에서 전달할 내용**

1. CLI를 통한 검사 요청 확인  
2. 진단 보고서와 첨부 파일 열람  
3. 검사체와 대화  
4. 의심 부위 추론  
5. 검사 부위 및 방식 선택  
6. 검사 결과 파일 확인  
7. 추가 검사 판단  
8. 기생체 반응 확인  
9. 감염 여부와 부위 보고  
10. 필요 시 비상 상황 대응

### **사례 구성 원칙**

튜토리얼은 다수의 복잡한 기생체를 소개하는 챕터가 아니다.

하나의 검사체를 중심으로 핵심 루프를 명확히 경험하게 하며, 결과 해석에 필요한 자료는 제한적이고 의도적으로 배치한다.

### **완료 기준**

별도의 외부 설명 없이 플레이어가 다음 사례부터 기본 업무를 스스로 진행할 수 있다.

---

## **11\. 초기 개발 범위에서 제외할 요소**

다음 요소는 핵심 루프 검증 이후로 미룬다.

* 전체 장기 구현  
* 다수의 검사 방식  
* 장기·검사·기생체의 모든 조합  
* 복잡한 질병 체계  
* 기생체 도감의 전체 기능  
* 공생체 판정  
* 네임드 NPC 중심 서사  
* 조직의 비밀과 다중 결말  
* 검사실 자유 탐색  
* 전투 시스템  
* AI 기반 동적 콘텐츠 생성

확장 가능성은 고려하되, 초기 구현 대상으로 취급하지 않는다.

---

## **12\. 최종 개발 판단 기준**

튜토리얼 챕터 완성 후 다음 항목을 검증한다.

* 문서와 대화가 실제 검사 선택에 영향을 주는가  
* 검사 결과가 해석 가능한 동시에 지나치게 명확하지 않은가  
* 추가 검사와 보고서 제출 사이에서 고민이 발생하는가  
* 2D 정보 처리와 3D 검사 연출이 분리되지 않고 하나의 경험으로 연결되는가  
* 검사체를 단순한 퍼즐 데이터가 아닌 살아 있는 대상으로 인식하게 되는가

이 기준이 충족되지 않는다면 콘텐츠를 확장하지 않고 핵심 루프를 우선 수정한다.
