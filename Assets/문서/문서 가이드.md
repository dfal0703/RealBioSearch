# 문서 가이드

> 이 문서는 Claude에게 제공할 목적으로 작성된 개발 가이드 프롬프트다.

## 1. 문서 폴더에 대한 설명

문서 폴더는 다음 6개의 항목으로 나뉜다.

1. 기획문서
2. 확장 기획
3. 구현현황
4. 정리 및 요약
5. 프레임워크
6. 에러 및 로그

### 기획문서 폴더

기획자에게 제공받은 직접적인 기획서가 들어간다.

- 이 폴더의 문서는 Claude가 **절대 임의로 수정해서는 안 된다.**
- 순전히 폴더 안의 내용을 이해하는 용도로만 사용한다.

### 확장 기획 폴더

기획자에게 제공받은 기획문서만으로는 다음 작업을 정할 수 없을 때(추가 기획이 더 이상
내려오지 않는 경우 등), 사용자와 Claude가 직접 협의해서 세우는 후속 기획이 들어간다.

- 기획문서 폴더와 달리, 이 폴더의 문서는 **Claude가 자유롭게 수정·보완할 수 있다.**
- 항상 기존 기획문서 폴더의 내용을 상위 규범으로 삼고, 위반하지 않는 선에서 구체화한다.
- 새 문서를 쓰기 전에 기획문서 폴더와 구현현황 폴더를 먼저 검토해 이미 다뤄진 내용과
  겹치지 않게 한다.

### 구현현황 폴더

지난 진행 상황과 현재 진행 상황 문서가 들어간다.

- 이 폴더의 문서는 Claude가 자유롭게 수정해야 하며, 후술될 개발 사이클을 통해 내용이 계속 갱신되어야 한다.
- 새 구현현황 문서가 생기면:
  - 이전에 쓰던 진행상황 문서 에 적혀있는 최종 수정 날짜 폴더를 `지난거` 폴더에 생성(예시: "07/14 현황")
    - 해당 문서 → 날짜 폴더에 이동
  - 새 문서 → `진행중` 폴더에 생성후 최종 수정 날짜를 맨 위에 기입

### 정리 및 요약 폴더

해당 프로젝트에 대한 정리나 요약 문서가 들어간다.

- 사용자가 내용을 잘 이해하지 못하거나 간단히 보고 싶은 경우, 정리 및 요약을 요청한다.
- 요청이 들어오면 문서를 생성해 "정리 및 요약" 폴더에 넣는다.
- 지난 내용과 현재 내용을 구분하지 않고 자유롭게 섞여 있어도 무방하다.

### 프레임워크 폴더

앞으로 사용할 프레임워크에 대한 문서가 들어간다.

- 대표적으로 Haare 프레임워크를 사용할 예정이며, 추후 사용자의 요청이 있을 것이니 해당 요청을 듣고 진행한다.

### 에러 및 로그 폴더

Claude에게 에러나 로그 내용을 보여줘야 하는 상황이 오면, 이 폴더 안의 `errors.md`, `logs.md` 문서에 그때그때 필요한 에러나 로그가 붙여넣어진다.

- Claude는 이를 참고한다.

## 2. 개발 철학

개발에 있어 기본 기조가 되는 철학을 다룬다.

1. 모든 코드는 Haare 프레임워크에 귀속된다.
2. 실행 가능한 상태를 만드는 것을 항상 목적으로 한다.
3. 하나의 기능 단위로 완성한다.
4. 모든 파일은 각자 제 자리에 맞는 폴더에 들어가야 한다. 중구난방으로 퍼져 있으면 안 된다.
5. Git Flow 브랜치 전략에 따라 브랜치가 분기된다.
6. 사용자의 재량이 필요한, Claude로서는 모호한 부분에 있어서는 항상 사용자에게 질문한다.
7. 구현 현황은 반드시 최대한 자세히 작성한다.
8. claude는 항상 한국어로 대답할것

## 3. 개발 사이클

Claude가 앞으로 진행할 개발 사이클은 다음과 같다.

1. 지시가 들어오면 "기획문서" 폴더에서 해당하는 문서 내용을 찾아 다시 검토한다.
2. 검토한 정보를 바탕으로 가장 최신 구현현황 문서(또는 새로 생성한 문서)에 구현 계획을 작성한다.
3. 그 계획에 따라 기능 단위로 구현을 진행한다.
4. 계획을 마치면 구현현황 문서에 구현 완료된 내용을 항목 단위로 나누어 작성한다.
